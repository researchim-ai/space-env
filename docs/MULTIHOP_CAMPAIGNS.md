# Многошаговая передача продуктов между спутниками

`space_env.tasks.multihop_campaign.multihop_campaign` добавляет цепочку
камера a → ретранслятор r → ретранслятор s → наземная станция.
Камера b использует b → s → Земля; обе доставки конкурируют за ресурсы s.
Съёмка, обработка, наведение, радиолинии, custody и энергетика исполняются
на том же непрерывном native runtime, что и в [relay campaigns](RELAY_CAMPAIGNS.md).

```python
from space_env.tasks.multihop_campaign import multihop_campaign
from space_env.industrial.campaign import AgentCampaignSession
from space_env.industrial.campaign_policy import campaign_policy

case = multihop_campaign({
    "horizon_sec": 240,
    "release_sec": 60,
    "fault_profile": "after_custody_recover",
})
session = AgentCampaignSession(case["configuration"])
session.step(
    campaign_policy(session.observe(), case["public_contract"]),
    expected_revision=session.revision,
    idempotency_key="first",
)
```

По умолчанию горизонт — два часа. Короткий профиль удобен для локальных тестов.
Дополнительные параметры: `forward_link_available=False` блокирует звено r→s
на весь горизонт, `sink_memory_bits` ограничивает память s. Настройки отказов,
TTL, ACK loss и задержанного маршрутного канала наследуются от
[routing campaigns](ROUTING_CAMPAIGNS.md).

## Физические и ресурсные ограничения

В этой постановке r передаёт в S-диапазоне 2.2 ГГц, s сбрасывает на Землю
в X-диапазоне 8.2 ГГц. Приёмник Late-Ground принимает 8.1–8.3 ГГц.
Прямой сброс r→Late-Ground недоступен по native RF budget; это не только
удаление команды из каталога. Для r→s задан отдельный S-band ISL-приёмник.
Обратное звено s→r имеет X-band ISL-приёмник и физически допустимо.
Оно присутствует для проверки политики, а не используется в успешном маршруте.

Каждый переход — существующий whole-product custody executor с сериализацией,
фрагментами, ACK и приёмным буфером. Владелец меняется после полного custody ACK.
Следующее звено не создаёт новый продукт и не продлевает исходный bundle TTL.
До ACK сохраняется исходная копия; затраты и незавершённая передача учитываются
штатным механизмом. Память, занятость и полудуплексные ограничения определяет
native executor. Политика не резервирует ресурсы вне исполнения команды.

## Объявленная топология и текущая доступность

`publish_route_topology=True` в конфигурации `AgentCampaignSession` добавляет
`relay_topology`: идентификатор действия, тип, аппарат, получатель и продукт
для relay/downlink-команд уже видимого каталога. Публикуется объявленная
возможность передачи, даже если продукт ещё не находится у этого аппарата.
По умолчанию публикация выключена. Фабрика multihop включает её явно.
Шаблоны будущих заявок фильтруются до публикации.

`relay_routes` по-прежнему описывает текущую доступность конкретной передачи
локально доступного продукта. В строки добавлены структурные расстояния
`source_hops_to_ground_sender`, `destination_hops_to_ground_sender` и
`makes_progress`. Они выводятся из объявленных команд видимых заявок,
не из rollout, будущих отказов или проверочного критерия успеха.
Если ground sender недостижим, расстояние равно `null`.

Расстояния вычисляются отдельно для каждого продукта обратным BFS от аппаратов,
у которых объявлена его downlink-команда. Ground sender имеет расстояние 0.
Узлы маршрута a→r→s имеют соответственно 2, 1, 0 relay-шагов.

## Защита от циклов в базовой политике

Публичный контракт `require_route_progress=True` требует включённого
`adaptive_routing`. Политика выбирает relay-команду только при доступном
маршруте допустимого возраста и `distance(destination) < distance(source)`.
Отсутствующие сведения не разрешают передачу.

На неизменном продуктовом графе последовательность неотрицательных целых
расстояний строго убывает, поэтому политика не может замкнуть цикл.
Обратная команда s→r отвергается, хотя радиолиния физически допустима.
Ограничение относится к базовой политике, а не к физике: произвольный агент
по-прежнему может выдать объявленную обратную команду и получить её последствия.

Это консервативная политика по числу шагов. Она не выбирает оптимальный путь
по энергии, надёжности или времени и не разрешает временный обход с увеличением
расстояния. Объявленный downlink не гарантирует реального окна связи;
неисправный аппарат или закрытая станция могут остановить маршрут.
Доказательство отсутствия циклов не переносится на произвольные изменения
топологии во времени без дополнительного протокола версий/истории маршрута.

## Проверки и данные для агентов

```bash
python -m pytest -q tests/test_multihop_campaign.py
python -m examples.modeling.multihop_campaign_study --output artifacts/my-multihop-study
python -m examples.modeling.multihop_campaign_audit artifacts/my-multihop-study
```

Проверяются продуктовые графы, циклы и недостижимые узлы, явное включение
progress gate, цепочка custody и неизменность TTL, отказы, память,
задержанные маршрутные снимки и checkpoint между двумя переходами.
Исследование включает двухчасовую миссию, сохраняет исходные эпизоды,
нативные сетевые отчёты и RL JSONL всех профилей. Успешная двухчасовая миссия
экспортируется также как SFT. Каждый экспорт повторно исполняет эпизод.
`scripted_public` означает демонстрационную политику, а не обученную LLM.

Профиль остаётся конструктивным и синтетическим: J2, заданные RF/RC/bus
параметры и идеальные внеполосные ACK. Задержка при включении затрагивает
только маршрутный канал; основной пульт остаётся текущим. Это не доказательство
физической точности реальной группировки, масштабирования на сотни аппаратов
или преимущества над другими симуляторами.

## Результаты локального исследования, 16 ноября 2026

Артефакты: `artifacts/multihop-campaign-20261116`.
Восемь профилей повторно исполнены при RL-экспорте; успешная двухчасовая
миссия дополнительно экспортирована для SFT. Четыре профиля успешны:
базовый, восстановление промежуточного радио, задержанный маршрутный канал
и двухчасовая миссия. Блокировка второго звена, малый буфер s, короткий TTL
и постоянная потеря радио владельца дали ожидаемый неуспех.

Базовый профиль завершил поздние доставки в t=81.08044 с, восстановление —
в t=85.35895 с при release=60 с. Двухчасовая миссия выполнила пять заявок
за 59 решений и сохранила достигнутый результат до t=7200 с;
последний поздний ACK — t=5849.59685 с.

Аудит 356 публичных наблюдений и сетевых отчётов проверил порядок custody,
неизменность TTL, происхождение действий, балансы битов и отсутствие
двойного наземного зачёта. Контролируемые искажения TTL, delivered bits
и обратный custody-переход отклонены отдельными отрицательными проверками.
Аудит отчётов не является дополнительным физическим replay;
повторное исполнение выполнено экспортёром эпизодов.

Проверены 81 различный локальный тест и installed-wheel smoke вне checkout:
39 решений с временным отказом, checkpoint между переходами,
совпадение 388 пакетных Python/JSON файлов.
