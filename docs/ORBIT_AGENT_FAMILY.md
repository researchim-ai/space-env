# Орбитальная постановка в общем интерфейсе агента

Обновление 15 ноября 2026 года добавляет пятое семейство:
`orbit_and_deployment`. Общее число запускаемых профилей — **21**. Три новых ID:
`phasing_2`, `phasing_4`, `phasing_8` — локальное фазирование 2, 4 и 8 аппаратов.

## Задача агента

Достичь опубликованных целевых положений и скоростей всех аппаратов в заданную
эпоху, сохранив минимальный запас топлива. Агент выбирает из видимых шаблонов
конечной тяги или ждёт. Управление централизованное с идеальным текущим состоянием.
Это не задача обучения оценке орбиты по сенсорам и не распределённое управление.

Прежняя реализация рецепта из example перенесена в
`space_env.tasks.deployment.deployment_recipe`. Сам example импортирует её из
пакета, поэтому installed wheel больше не требует импортировать файл из examples.
Физический runtime, независимый RK4 расчёт целей и прежние критерии сохранены.

Новый `OrbitSession` — адаптер над `TaskSession`, а не второй интегратор.

- `OrbitAction` принимает только `action_ids` (до 8); произвольные команды,
  события и изменение цели не предоставляются.
- Выполнение, длительность, native admission, reward, goal и расход ресурсов
  остаются у TaskSession.
- Observation содержит центральный native view, опубликованную цель и scope;
  binding пересчитывается после смены пространства ревизий.
- Replay фиксирует native checkpoint и результаты. Повторный idempotency key
  не исполняет манёвр повторно.
- Ошибочные неизвестные ID отклоняются до изменения физики. Известные действия,
  отвергнутые native admission, сохраняют native semantics и обратную связь.
- Call budget Gym обозначается как truncation; native truncation также не
  преобразуется в успешное физическое завершение.

## Физика и критерий

В этом рецепте используется центральное поле и конечная инерциальная тяга:

\[
\dot{\mathbf r}=\mathbf v,\qquad
\dot{\mathbf v}=-\mu\frac{\mathbf r}{\|\mathbf r\|^3}
 +\frac{F}{m}\hat{\mathbf d},\qquad
\dot m=-\frac{F}{I_{sp}g_0}.
\]

Шаблоны прикладывают тягу 2 N в течение 20 s; критерий оценивается в 60 s.
Направления вдоль/против исходной скорости чередуются между аппаратами.
Цели рассчитываются отдельно фиксированным RK4 с шагом 0.005 s с теми же
константами и входами и аналитическим изменением массы. Допуски конечного
состояния: 0.01 m и 0.00001 m/s; резерв топлива ≥9.98 kg. Это проверка согласия
данного интегрирования с конкретным численным эталоном, а не заявленная точность
реального спутника или независимая аппаратная калибровка.

Данный рецепт **не моделирует** многодневное развёртывание, выпуск аппаратов
из носителя, раскрытие панелей, ориентацию двигателя в body frame, J2/drag/SRP
при этом манёвре, контактную динамику, непрерывную безопасность сближений или
переход к передаче прикладных данных. Ресурсная модель — существующий native
surrogate. Остальные native орбитальные задачи остаются в отдельном каталоге;
это обновление не переносит их автоматически в новый адаптер.

## Использование

```python
from space_env.industrial.missions import make_episode, make_env, run_mission
from space_env.industrial.agent import verify_episode

# Цель и JSON tool доступны тем же способом, что у других семейств.
episode = make_episode(
    "orbit_and_deployment/phasing_4",
    split="train", policy_origin="external_llm", max_calls=32,
)

# Или scripted policy для локальной проверки:
record = run_mission("orbit_and_deployment/phasing_2", policy="public")
verify_episode(record)

env = make_env("orbit_and_deployment/phasing_8", max_calls=32)
observation, info = env.reset()
env.close()
```

```bash
python -m space_env.industrial.missions \
  --mission orbit_and_deployment/phasing_4 --policy public \
  --output artifacts/new-orbit-record.json
```

`public` выбирает все видимые разрешённые шаблоны при t=0, затем ждёт.
Это намеренно простой baseline для фиксированного рецепта. Он не решает
произвольный выбор траектории и не показывает преимущество LLM или RL.
Расписание эталона (`reference_steps`) в сообщения агента не добавляется.

## Верификация и дальнейшая работа

Тест сравнивает native checkpoints, цели, reward, feedback и время TaskSession
с адаптером после каждого из 12 решений. Также проверены fuel reserve,
неизвестные/дублированные действия, JSON checkpoint restore, idempotency,
успешный SFT/RL export, провал wait и Gym call budget.

Следующий содержательный шаг — разнообразить саму постановку: разные доступные
времена и направления манёвров, бюджеты и эпохи, конкурирующие ограничения,
проверенные физически допустимые и недопустимые варианты. Затем — удержанные
семейства генерации, более долгие миссии и совместное планирование наблюдения
и связи. Три размера одной фиксированной задачи не заменяют это разнообразие.

[Общий интерфейс семейств](AGENT_MISSION_FAMILIES.md) описывает предыдущий этап.
Его старые приёмочные записи остаются связанными с прежними исходниками;
результаты этого обновления записываются отдельно.

### Измеренные результаты обновления

- 44 целевых теста прошли, включая побайтовое сравнение native checkpoints
  после каждого шага адаптера и прямого TaskSession, а также отклонение
  подделанного state witness после пересчёта внешней печати.
- Шесть полных эпизодов повторены через `verify_episode`: `wait` не выполнил
  цели для всех трёх размеров; scripted `public` выполнил все 2/4/8 целей.
  Все полные прогоны закончились в t=60 s, successful runs сохранили заданный
  резерв топлива. Это не доказательство решения произвольных орбитальных задач.
- Одна train-демонстрация с двумя аппаратами экспортирована как SFT и как RL
  после replay. Обучение модели не проводилось; holdout-генерация не создавалась.
- Wheel 0.134.0 содержит 369 побайтово совпадающих Python/JSON файлов. Из отдельного
  cwd выполнены discovery и двухшаговый запуск орбитального профиля с replay.
  Использовались существующие зависимости: это не clean-install qualification.

Артефакты: `artifacts/orbit-family-20261115/`, игнорируются Git. Старые receipts
не перепривязывались к новым исходникам.

Дополнительно прошли **122 регрессионных теста** остальных industrial/native
сред и прежнего каталога миссий — всего 166 разных тестов в двух наборах.
[Приёмочная запись](acceptance/ORBIT_AGENT_FAMILY_V1.json) фиксирует manifest
исходников и хеши 16 локальных артефактов, включая результаты, экспорты и wheel.
