# Следующий уровень среды спутниковых AI-агентов

Дата: 8 ноября 2026. Версия пакета остаётся 0.134.0. Этот документ описывает
реализацию и критерии завершения; наличие модуля само по себе не считается
подтверждением качества миссии, обучения или превосходства.

## Измеренный результат пакета

- **357 distinct local tests passed:** три непересекающиеся группы 66/126/165,
  полный repository suite не запускался. Журналы восстановлены после прерывания
  в `artifacts/ai-advancement-20261108/`; этот каталог уже игнорируется Git.
- **32/32** аналитических физических сравнения прошли. Это core и reference
  rigid kernel, без внешнего engine и аппаратной калибровки.
- **10/10** исполнений operations-suite из собранного wheel повторены аудитом.
  Reference policy закрыла 4/5 операционных целей; ограниченная разгрузка
  сохранилась как отрицательный случай. Wait не закрыл ни одну цель.
- Проверена вся scale-лестница, workers=2: `tiny 0/1`, `pair 0/3`,
  `reference 3/3`, `backlog 3/8`, `boundary 2/16`. Во всех случаях число native
  доставок совпало с планом, failed calls отсутствуют. `qualified=true` означает
  replay/resource integrity и совпадение с планом, **не** выполнение всех заявок.
  В boundary 240 решений; native execution около 79 s, replay около 80 s,
  максимальный phase VmHWM около 452 MB, parent-observed RSS около 454 MB.
  Это единичные наблюдения при параллельной локальной валидации, не чистый
  throughput-бенчмарк и не доказательство масштаба тысяч аппаратов.
- Сквозная генерация: четыре выбранных публичных миссии, все 3/3 доставлены;
  train содержит **2 RL episodes + 2 native SFT conversations** на одной train
  геометрии. Две другие геометрии development/test остались только в audit.
  Подготовлено **72 semantic train decisions: 29 active + 43 wait**, 0 потерянных
  представимых решений. Реального provider wire-SFT нет; teacher scripted_privileged.
- Wheel byte-matched с 319 package Python modules и packaged operations fixture;
  установленный payload проверен с cwd вне checkout. Это существующее dependency
  окружение, не dependency-clean установка.

Приёмка: [AI_ADVANCEMENT_BUNDLE_V1.json](acceptance/AI_ADVANCEMENT_BUNDLE_V1.json).
Реального обучения/инференса Qwen в этом пакете не было. GGUF checksum проверен,
но HF checkpoint не найден, а training stack имеет NumPy ABI import error.
Следующая очередь: [AI_NEXT_EXECUTION.md](AI_NEXT_EXECUTION.md), начиная с общего
goal/reward контракта для новых классов задач.

## Цель

Общий процесс: конфигурация миссии → наблюдения и действия агента → native
исполнение → проверяемые эпизоды → SFT/RL → оценка на отдельных задачах.
Сохраняем единый runtime, контроль доступа и физические ограничения. Численные
RL/MARL-интерфейсы и LLM tool-use решают разные задачи над одной миссией.

## Реализованные компоненты этого пакета

- [Sequence recovery](SEQUENCE_RECOVERY.md): residual-first продолжение и новый
  suffix из committed pose; явные ограничения и serial fallback.
- [Learning experiment](LLM_LEARNING_EXPERIMENT.md): проверка корпуса, semantic
  targets, assistant loss mask, offline LoRA workflow и аудит парных rollout.
  Реальный Qwen3.5 SFT заблокирован отсутствием HF checkpoint и совместимого
  импортируемого training stack. Это экспериментальная реализация, не измеренный
  результат обучения.
- [Physics reference](AI_PHYSICS_REFERENCE.md): 32 аналитические проверки core и
  reference rigid kernel с fixed tolerances, corruption tests и source seals.
  Внешний engine и аппаратная калибровка не выполнялись.
- [Operations suite](LLM_OPERATIONS_SUITE.md): пять packaged cases, три семейства,
  два scripted baseline; разгрузка маховиков имеет свой native evaluator.
- [Sequence scale](SEQUENCE_SCALE.md): пять frozen нагрузок, 1–4 отдельных
  процесса, измерения и native audit, сохранение отрицательных результатов.
- [Paired evaluation](PAIRED_AGENT_EVALUATION.md): восстановление frozen case,
  одинаковые условия, фиксированные знаменатели и geometry-cluster bootstrap.

Эти ограниченные компоненты не закрывают весь долгосрочный roadmap. Измеренные
результаты конкретной сборки фиксируются отдельно в журнале и acceptance receipt.

## Свежие данные для проверки интеграции

```bash
python -m examples.llm.advancement_demo --output /tmp/ai-advancement-demo
```

Скрипт заново исполняет четыре заранее выбранных public cases: два train на одной
геометрии, один development и один test на других геометриях. Создаёт verified
corpus и регистрирует его в SQLite, затем готовит semantic SFT targets только из
train. `--registry /path/shared.sqlite` подключает общий registry остальных
производителей; default DB локальна этому demo и не обеспечивает глобальную
защиту между независимыми DB.

Пропущенные роли в успешном native teacher означают неявное ожидание. Конвертер
сохраняет их как `wait`, не теряя активные команды; эквивалентность проверяется
состоянием native runtime на каждом шаге. Отдельно учитываются active/wait/finish
targets. Положительный корпус, превратившийся только в wait/finish, отклоняется.

Это свежая интеграционная демонстрация scripted privileged teacher, не полная
36-case qualification, не model-generated wire-SFT и не оценка обучения Qwen.

## Порядок и критерии закрытия

### A. Восстановление динамической миссии

- Использовать committed prefix: текущую ориентацию, остатки CPU, владельцев
  продуктов, остатки передачи, TTL и уже подтверждённую доставку.
- Планировать остаток с реальными ресурсными полосами; не переносить начальную
  геометрическую гарантию на изменившееся состояние.
- Проверить новые заявки, изменение приоритетов, частичные raw/final-продукты,
  недоступность станции/аппарата, сохранность source branch и native replay.
- Явно ограничить поддерживаемые состояния; неподдерживаемый случай получает
  консервативный fallback или отказ, а не ложную гарантию.

Приёмка: законченные native recovery-прогоны и отрицательные проверки; отдельно
качество доставок и целостность восстановления. Оптимальность не предполагается.

### B. Настоящий эксперимент обучения LLM

- Зафиксировать train/development/test и модель до начала эксперимента.
- Проверять корпус, geometry split, маскирование assistant target, токенизацию
  и отсутствие операторской информации в входах policy.
- Запустить базовую и обученную модели с одинаковыми каталогами, состояниями,
  бюджетами и настройками генерации; сохранить реальные provider responses.
- Сохранять ошибки и отрицательные эпизоды. Отдельно считать успех цели,
  доставленный приоритет, ошибки tools, стоимость и задержки.
- Доказательство обучения требует действительных весов после training и
  сравнения на evaluation. Тестовый маленький transformer не является Qwen3.5.

Локальная граница: GGUF для inference не заменяет обучаемый HF checkpoint.
Отсутствие нужных весов/исполняемого runtime фиксируется как блокировка
эксперимента, а не как выполненный SFT. Другую модель молча не подставляем.

### C. Независимые физические эталоны

- Для каждого тестируемого профиля задать equations, units/frames, tolerances,
  длину дуги и исключённые эффекты до измерений.
- Разделить аналитические решения, независимый внешний engine и реальные
  измерения. Совпадение с формулой не является аппаратной калибровкой.
- Проверять не только положительные значения, но и способность suite обнаружить
  испорченную модель.
- Затем добавить согласованные whole-mission comparisons с внешним engine.
  Пока такой прогон не выполнен, превосходство над Basilisk/Orekit не установлено.

### D. Новые операционные постановки

Первый шаг — небольшие проверяемые семейства над уже существующим runtime:
конкуренция за ресурс, доставка/custody и восстановление операций. Для каждого
нужны настоящие различающиеся входы, native objective и отрицательный baseline.
Не называть заранее известный outage неожиданным событием.

Следующий отдельный пакет — полноценные задачи управления ориентацией,
орбитальных манёвров, инспекции и диагностики с собственными наблюдениями,
действиями и safety/completion evaluator. Наличие вспомогательной физической
модели не означает готовность соответствующего агентного benchmark.

### E. Измеренный масштаб

- Заморозить workload до запуска; увеличивать actors, requests и horizon
  внутри объявленных ограничений профиля.
- Измерять отдельно compile/planning, native execution, peak RSS и integrity.
- Исполнять в отдельных процессах с ограниченными workers/timeouts; ошибки и
  превышения бюджета сохраняются.
- Не выдавать 4 аппарата/1200 секунд за тысячи аппаратов/месяцы миссии.
- Прежние large-scale профили не квалифицируют автоматически новый planner.

### F. Сравнимый benchmark

Парное сравнение требует идентичных начальных checkpoint, каталога, текста
задачи и бюджета tools. Входной native record повторяется исполнением, а не
принимается по подписи JSON. Пропуски и инфраструктурные ошибки остаются
неизвестными значениями в фиксированном знаменателе.

Коррелированные варианты одной геометрии объединяются при оценке
неопределённости; нельзя считать отдельные decision ticks независимыми миссиями.
Public regression splits не становятся blind/OOD от переименования.

Для внешнего сравнения дополнительно нужны адаптер конкурента, согласованные
physics/action/observation/time contracts и его настоящий запуск. Сам по себе
внутренний benchmark этого не доказывает.

## Локальный порядок проверки

Точные команды и фактические результаты каждого пакета сохраняются в его
документе и общем журнале PRODUCT_EXECUTION_NEXT.md. Проверяем локальными
тестами и runnable examples. CI, публикацию, commit и push не добавляем.

Все source-bound измерения делать после завершения изменений Python-модулей:
исторический отчёт сохраняет свою ревизию и не подтверждает новый код.

## Что не закрывается одним программным пакетом

Измерения реального оборудования, клиентский pilot, flight qualification,
универсальное превосходство и качество переноса на неизвестные миссии требуют
соответствующих внешних данных и экспериментов. До них допустимы только
ограниченные утверждения по реально выполненным проверкам.
