# Длительная двухаппаратная кампания

`space_env.tasks.long_campaign.long_campaign` компилирует воспроизводимую
синтетическую миссию с двумя активными аппаратами и непрерывным физическим clock.
Результат подключается к существующим AgentCampaignSession, JSON-инструментам,
Gym и проверяемому экспорту данных для SFT/RL.

## Постановка

1. Аппарат a снимает, обрабатывает и доставляет три начальных запроса до t=20.
2. После длительного участка полёта аппарат b получает новую заявку, выполняет
   съёмку и преобразование продукта, затем доставляет результат на другую станцию.
   Во время этой работы станция временно недоступна и восстанавливается внешним событием.
3. Миссия продолжается до заданного горизонта. Проверяются сохранность записей
   об успешных доставках, история исправности и накопленные расходы энергии.

Между фазами нет новой батареи, нового orbit runtime или очистки продуктов.
Это централизованное управление двумя аппаратами, не распределённый multi-agent
протокол и не оптимизация назначения исполнителей: исполнители объявлены в заявках.

## Конструкция окна наблюдения

По умолчанию поздняя заявка приходит примерно через номинальный центральный
орбитальный период: 2π√(r³/μ), около 5828.5 секунды для данного начального радиуса.
Это время не считается точным периодом J2-орбиты.

Место съёмки заранее строится как пересечение WGS84 с фиксированной оптической
осью аппарата b в середине номинального двухсекундного acquisition. Положение
для конструкции вычисляется на отдельной более частой J2-эфемериде. Затем AOI,
станция и синтетическая clear-sky маска становятся неизменяемой постановкой.
При изменении настроек исполнения эта конструкция не меняется.

Таким образом, это **намеренно сконструированная возможность наблюдения**,
а не blind holdout и не доказательство выполнения произвольных заказов.
Native runtime по-прежнему проверяет геометрию, оптическое качество, площадь
покрытия, ориентацию, память, CPU, связь и поступление продуктов.

Будущая заявка отсутствует в живом runtime до события request_added. Её imaging,
transform и downlink шаблоны имеют request_ref и скрыты из публичного каталога
до поступления. Политика не получает будущие времена, координаты или phase goals.
Начальная инфраструктура станций и оснащение аппаратов считаются известными.

## Физический профиль и ограничения

- Два раздельных распространяемых GCRS состояния с J2 и пакетными EOP.
- Coupled bus: заряд, эффективность разряда, кинематическая ориентация,
  потребители payload/CPU/radio, однозвенная RC-тепловая модель.
- По 100 Wh батареи на аппарат, начальный SOC 0.8. Профиль battery-only:
  солнечная генерация равна нулю, батарея не увеличивается по мере выполнения.
- Balanced: шаг выдачи орбитальной эфемериды 30 s, максимальный шаг DOP853 60 s,
  native lifecycle grid 5 s. Управляющие команды и события могут давать более
  короткие границы. Точность не выводится автоматически из этих размеров шага.
- Детальный орбитальный профиль: 1 s / 5 s, при том же lifecycle grid.
- Идеальная текущая телеметрия без навигационного estimator; передача по объявленной
  скорости с геометрическими контактами и outages, без детального RF-канала.
- Нет drag/SRP/third-body, rigid/wheel ADCS, детального thermal network, реального
  радиооборудования или межспутниковой передачи в этой конкретной постановке.
- Продукты — native геометрические/ресурсные артефакты, не фотореалистические снимки.

Библиотечные границы данного генератора: 120–21600 s, при коротком горизонте
нужно явно указать более ранний release_sec. Фиксированная оптическая ось может
не пересечь Землю для произвольного времени; тогда компиляция отклоняется.
Настройки батареи и временных сеток явные, а не аппаратно откалиброванные.

## Управление и публичная инструкция

```python
from space_env.tasks.long_campaign import long_campaign
from space_env.industrial.campaign import AgentCampaignSession
from space_env.industrial.campaign_policy import campaign_policy

case = long_campaign()
session = AgentCampaignSession(case["configuration"])
action = campaign_policy(session.observe(), case["public_contract"])
```

Публичный контракт задаёт четыре доставки и адаптивное ожидание до 300 секунд.
Для этого max_wait_sec теперь допускает до 3600 s; фактический интервал дополнительно
ограничен task.max_decision_sec, видимыми таймерами и границами native событий/целей.

При создании IndustrialEpisode **явно сообщайте агенту требование оставаться
на дежурстве до horizon_sec**, начальные/поступившие SLA и ресурсные ограничения.
Нельзя требовать угадывать endurance-фазу по скрытым целям. Квалификационный
драйвер передаёт такую публичную инструкцию в task_text; будущего расписания в ней нет.

## Локальное воспроизведение

```bash
python -m examples.modeling.long_campaign_study --output artifacts/my-long-campaign
python -m examples.modeling.long_campaign_convergence artifacts/my-long-campaign
python -m pytest -q tests/test_long_campaign.py
```

Первый драйвер исполняет двухчасовой balanced и более детальный орбитальный
вариант, шестичасовой вариант и отрицательный пример с батареями по 1 Wh.
Каждая RL-строка проходит native replay внутри export_training; из основного
двухчасового варианта также сохраняется SFT. Не создаются дублирующие SFT из
каждой смены сетки. Происхождение политики — scripted_public, не LLM inference.

Сравнение эфемерид проверяет одинаковость постановки за исключением объявленных
орбитальных настроек и вычисляет различия на общих временах публичных наблюдений.
Это сходимость при изменении сетки **одной и той же физической модели**, не
независимый эталон и не гарантия ошибки между отсчётами. Отдельно сравнивается
конечное состояние. Локальное wall time не является сравнением с конкурентами:
нагрузка хоста не контролируется, replay/export учитываются отдельно.

## Что остаётся

Следующие расширения: повторяемые многоволновые заявки с произвольной геометрией,
планирование ориентации и энергетики, ISL и общие наземные ресурсы в том же длинном
runtime, затем более крупные группировки. Нужны независимые физические эталоны,
аппаратные данные и отдельные профили реализма. Этот сценарий сам по себе не
подтверждает промышленную готовность, сутки работы или преимущество над другими системами.

## Зафиксированный результат — 16 ноября 2026

Квалификационный прогон: `artifacts/long-qualified-campaign-20261116`.
Двухчасовой профиль завершился на t=7200 за 48 решений; шестичасовой — на
 t=21600 за 96 решений. В обоих случаях аппарат b получил новую заявку около
 t=5828.52 и выполнил её после временной недоступности второй станции.
Четыре доставки и три фазы проверены native evaluator.

При батареях по 1 Wh обе волны были выполнены, но endurance-фаза завершилась
провалом в t=390 из-за состояния аппаратов. Накопленные расходы не обнулились.

В орбитальной паре совпали 49 времён наблюдения. Максимальное различие GCRS
положений составило 0.02018 m, скоростей — 0.002072 m/s. Это различие сеток
одной J2-модели на этих отсчётах, не погрешность относительно настоящей орбиты.
Максимальные ошибки учёта во всех четырёх эпизодах: менее 4.4e-12 Wh и 1.3e-9 J.

Пройдены 53 локальных теста. Получены четыре RL-строки и одна SFT-строка с явно
сообщённым публичным endurance-требованием. Это алгоритмическая публичная политика,
без inference/тренировки модели. Генератор и 240-секундная миссия также выполнены
из установленного wheel вне checkout; совпали 381 Python/JSON-файл.

[Source-bound свидетельство](acceptance/LONG_CAMPAIGNS_V1.json) связывает код,
окружение, записи и сравнения. Разработческие прогоны с неполной публичной
инструкцией исключены из квалифицированных обучающих данных.
