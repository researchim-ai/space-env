# Относительное движение и цели группового полёта

Инженерный пакет 9 ноября 2026. Новая цель `relative_orbit` использует **две
фактические динамические орбиты native runtime**, а не прогноз CW и не
подставленный план. Она расширяет общий контракт [физических целей](PHYSICAL_MISSION_GOALS.md):
SDK, Gym/PettingZoo, LLM finish, checkpoint replay, reward и SFT/RL gates.

## Что можно задавать

Относительное положение и скорость аппарата `actor` относительно
`reference_actor` в фиксированный момент, последовательность таких контрольных
точек, допустимую ошибку и минимальную дистанцию. Это основа задач группового
полёта и маневрирования относительно другого аппарата; контактная динамика,
стыковка, сенсорная навигация и автономный оптимальный rendezvous solver сюда
не входят.

```json
{
  "schema": "space-env.mission-goal/1",
  "deadline_sec": 5.0,
  "conditions": [{
    "id": "formation-point",
    "kind": "relative_orbit",
    "actor": "a",
    "reference_actor": "b",
    "frame": "GCRS",
    "at_sec": 5.0,
    "position_m": [-100.0, 0.0, 0.0],
    "velocity_m_s": [0.0, 0.0, 0.0],
    "position_tolerance_m": 0.1,
    "velocity_tolerance_m_s": 0.01,
    "min_range_m": 50.0,
    "require_command": true,
    "completion": "achieve"
  }]
}
```

Это иллюстрация recipe, не утверждение достижимости данных чисел произвольным
аппаратом. Исполнимые фиксированные recipes находятся в `modeling_suite`.
Для естественного относительного дрейфа допустим `require_command: false`.
При `true` требуется законченная native команда манёвра `actor`; намерение,
отклонённая команда или манёвр только опорного аппарата доказательством не служат.

## Уравнения и кадры

Цель в GCRS вычисляется непосредственно из состояний двух аппаратов:

\[
\rho_I=r_a-r_b,\quad \dot\rho_I=v_a-v_b,\qquad
\|\rho_I-\rho_*\|_2\leq\epsilon_r,\quad
\|\dot\rho_I-\dot\rho_*\|_2\leq\epsilon_v.
\]

Оба условия проверяются в окне `abs(time_sec-at_sec) <= time_tolerance_sec`.
Знак всегда **actor минус reference**. Величины — метры, секунды, м/с.
Нулевая относительная скорость в GCRS не означает удержание постоянного места
во вращающемся RTN. Поле `frame: RTN` в recipe отклоняется, чтобы эти скорости
нельзя было молча перепутать.

Для работы с RTN добавлены `relative_state_rtn` и `rtn_state_to_eci`
в `space_env.core.relative`. Это точные мгновенные преобразования координат,
не модель распространения движения. Пусть столбцы B — единичные R,T,N
опорного аппарата. Тогда:

\[
\rho_R=B^T(r_a-r_b),\qquad
\dot\rho_R=B^T(v_a-v_b)-\omega_R\times\rho_R.
\]

\[
\omega_R=\left(\frac{\|r_b\| a_N}{\|r_b\times v_b\|},\;0,\;
\frac{\|r_b\times v_b\|}{\|r_b\|^2}\right),\quad a_N=N\cdot a_b.
\]

Опциональная `reference_acceleration` учитывает поворот орбитальной плоскости
при нормальном ускорении; без неё предполагается `a_N=0`. Использование простой
`eci_to_rtn(delta_v, ...)` не даёт производную относительных RTN-координат.
Вырожденные радиус/момент, неверные размеры и нечисловые состояния отклоняются.

Линейная CW-модель остаётся отдельным приближением для близких аппаратов около
круговой опорной орбиты; цель проверяется по native состояниям без CW-линеаризации.
`closest_approach` теперь заканчивает сетку точно на horizon, не ищет минимум
за его пределами и проверяет корректность шага. Это **сеточный**, не непрерывный
минимум; число интервалов ограничено миллионом.

## Доступ, безопасность и восстановление

- Любая роль, которой принадлежит `actor`, должна также владеть `reference_actor`.
  Иначе TaskSession отклоняет задачу: разность истинных состояний раскрывала бы
  чужую телеметрию. Это текущий режим совместного управления, не имитация
  межспутникового сенсора или безусловного обмена телеметрией.
- `min_range_m` проверяется в начальном состоянии и на committed границах шагов,
  включая промежуточные waypoint. Нарушение `relative_keepout:<id>` необратимо
  для этого episode. **Между границами столкновение может быть пропущено.**
  Нет swept-volume, непрерывного collision detector, ковариаций или probability
  of collision. Нельзя использовать эту проверку как полётную гарантию.
- Время шага обрезается на следующей ещё не достигнутой контрольной точке.
  `achieve` сохраняет выполненный этап; reward не начисляется повторно.
  `maintain` требует соответствия текущему состоянию и далее.
- Native replay восстанавливает этапы и нарушения из исполненных переходов;
  editable флаг успеха не заменяет физическое доказательство.
- Общие бюджеты энергии/топлива действуют вместе с относительной целью.

Для relative tasks численное наблюдение `goals` имеет размер **16×37**:
к прежним 34 столбцам добавлены `reference_index`, `range_m`, `min_range_m`.
Есть маски отдельных значений; индекс reference связан с entity index наблюдения.
`kind_code=6`. Пространство прежних пяти типов без relative condition остаётся
16×34; пространство no-goal задач не меняется. Имена доступны через Gym info
`goal_feature_names`. Форма пространства определяется recipe, а не ходом episode.

## Воспроизводимая проверка

```bash
python -m pytest tests/test_relative_mission_goals.py -q
python -m space_env.tasks.modeling_suite --output artifacts/relative-study
python -m space_env.tasks.modeling_suite --audit artifacts/relative-study
```

Матрица расширена до **19 fixed public synthetic cases × 2 policies = 38 запусков**.
Шесть новых случаев: манёвр, неверное направление тяги, две контрольные точки,
начальное нарушение keepout, ошибка заданного положения, пассивное движение.
Эталон обеих орбит — отдельный fixed-step RK4 `h=0.005s`, центральная гравитация,
короткий интервал 5s; манёвр — постоянная инерциальная тяга с расходом массы.
Общие константы/начальные условия, разные реализации распространения. Это
инженерный численный эталон, не экспериментальная точность 1 мм на реальном КА.

Позитивные native relative trajectories допускаются в SFT, неуспешные — только
в RL. Используется scripted teacher, не обученная LLM. Геометрия фиксирована,
нет blind holdout, внешнего competitor benchmark или аппаратной калибровки.

Локальный результат: **238 различных тестов прошли** (33 новых + 102 регрессии +
103 LLM/data). Source и установленный wheel отдельно выполнили и воспроизвели
по 38 запусков без runtime ошибок. Reference решил 12/19, wait 1/19 (пассивный
случай); семь отрицательных reference outcomes сохранены. Полный repository
suite не запускался. Wheel проверен побайтово по 334 Python/JSON файлам;
зависимости использовались из текущего окружения.

Два новых train-прогона через общий SQLite split registry создали **2 RL episodes
и 1 native SFT conversation**: успешный `relative-nominal` и неуспешный
`relative-wrong-direction`. Негативный случай не попал в SFT; wire-SFT 0.
Геометрия одна фиксированная, обобщение на новые орбиты этим не доказано.

```bash
python -m examples.modeling.mission_goals --case relative-nominal \
  --split train --registry artifacts/shared-relative-registry.sqlite \
  --output artifacts/new-relative-positive
python -m examples.modeling.mission_goals --case relative-wrong-direction \
  --split train --registry artifacts/shared-relative-registry.sqlite \
  --output artifacts/new-relative-negative
```

[Приёмка с исходниками, журналами и артефактами](acceptance/RELATIVE_MISSION_GOALS_V1.json).
Предыдущие source-bound receipts относятся к своим историческим исходникам,
а не автоматически к текущему состоянию проекта.

## Следующие отдельные пакеты

1. Наблюдаемое относительное состояние: дальность/range-rate/углы, шум, bias,
   частота, задержки, dropout, фильтр и его ковариация. Не отдавать native truth
   вместо измерения; проверять consistency и наблюдаемость.
2. Непрерывные сближения: event localization или консервативный swept interval,
   конечные размеры аппаратов, подход/уход, гарантированные fail cases.
3. Более длинные maintenance/formation миссии, perturbations и разнообразные
   начальные орбиты с разделёнными train/test геометриями.
4. Замкнутое управление с ограниченными средствами измерения и реальным
   каталогом допустимых манёвров; сравнение с независимым solver/симулятором
   только при согласованных моделях, входах и метриках.
