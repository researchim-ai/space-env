# Каталог исполняемых миссий

Каталог объединяет 28 существующих синтетических рецептов в единую точку
обнаружения, экспорта и запуска. Это не 28 новых физических моделей и не
28 независимых промышленных классов миссий.

## Что доступно

- `physical/`: 19 задач ориентации, разгрузки маховиков, тяги в связанных
  координатах, достижения орбитального состояния, относительного движения
  и доставки продуктов. Сохраняются отрицательные варианты и ограничения
  исходных задач.
- `navigation/`: три задачи доставки с оценкой состояния вместо точного
  орбитального состояния: номинальная, задержки/потери, отсутствие контакта.
- `finite/`: шесть задач конечной инерциальной тяги с оцениванием и доставкой:
  центральная гравитация, J2, совокупность поддержанных возмущений,
  отмена манёвра, недопустимая тяга, нехватка топлива.

Для каждого рецепта каталог содержит исполнителей, полномочия ролей,
исходный критерий успеха, требования к моделям, режим наблюдаемости,
SHA-256 рецепта и расписание опорных действий с временными границами.
Расписание — инструкция привилегированной демонстрационной политики.
Оно не является автоматом фаз миссии, оптимальным планом или гарантией успеха.

## Использование

Из корня репозитория:

```bash
python -m space_env.tasks.catalog --output artifacts/missions/catalog.json
python -m space_env.tasks.catalog --mission finite/finite-j2 --output artifacts/missions/recipe.json
python -m space_env.tasks.catalog --mission finite/finite-j2 --run reference --output artifacts/missions/reference.json
python -m space_env.tasks.catalog --mission finite/finite-j2 --run wait --output artifacts/missions/wait.json
```

После установки также доступна команда `space-env-missions`.
Файл назначения должен быть новым: существующие результаты не перезаписываются.

Python API:

```python
from space_env.tasks.catalog import mission_catalog, mission_recipe, run_mission

catalog = mission_catalog()
recipe = mission_recipe("finite/finite-j2")
record = run_mission("finite/finite-j2", policy="reference")
```

Исполнение проходит через тот же `TaskSession` и actor-only инструменты
`LLMEpisode`, что и задачи для агентов. Готовая запись проверяется штатным
`verify_record`. Для RL/SFT используйте существующий экспорт эпизодов;
пригодность для SFT определяется метриками записи, а не наличием расписания.
Экспорт рецепта содержит привилегированный опорный план: не передавайте его
целиком оцениваемому агенту и не смешивайте его с акторными наблюдениями.

## Границы и дальнейшее расширение

Обнаружение рецептов не запускает миссии; построение рецептов может вычислять
синтетические эталонные цели. Наличие в каталоге не доказывает физическую
калибровку. Согласованные модели сил используют общие с native физические
функции и не являются независимой валидацией. Относительные ограничения
контролируются на дискретных границах, а не непрерывно.

Произвольное склеивание рецептов запрещено архитектурно: каталог не предлагает
такой операции. Для последовательных фаз теперь существует отдельный `CampaignSession`,
сохраняющий один runtime, продукты, состояние фильтра, топливо и ресурсы.
Каталог по-прежнему экспортирует отдельные task-эпизоды; автоматическое
превращение произвольного набора рецептов в кампанию не реализовано.

Следующие крупные миссии следует добавлять через новые проверяемые рецепты:

1. Длительное поддержание орбиты и фазирование с возмущениями и ограничениями
   ресурса двигателей, термики и энергетики.
2. Инспекция и сближение с наблюдаемой относительной навигацией, abort и
   непрерывным контролем безопасности.
3. Составная EO-миссия: съёмка, обработка, ISL, доставка и перепланирование
   при новых заявках и отказах в одном живом runtime.
4. Телекоммуникационная миссия с потоками трафика, QoS, лучами и handover.
5. Стыковка и обслуживание только после реализации контактной динамики.

Для каждого расширения обязательны положительные и отрицательные сценарии,
явное описание наблюдаемости, независимые проверки там, где они доступны,
и отсутствие скрытого truth в данных агента.

Для фаз в одном живом runtime добавлен отдельный
[контракт составных миссий](COMPOSED_MISSIONS.md). Он принимает единый scenario
и TaskSpec; автоматическое склеивание произвольных рецептов по-прежнему
не поддерживается.
