# Обходные маршруты и восстановление связи

`space_env.tasks.detour_campaign.detour_campaign` расширяет непрерывную
миссию до пяти аппаратов. Для позднего продукта камеры a объявлены
пути a→r→s и a→r→t→s; камера b использует b→s. Аппарат s выполняет
X-band доставку на Землю. По умолчанию r→s недоступен, поэтому нужен
дополнительный S-band ретранслятор t.

```python
from space_env.tasks.detour_campaign import detour_campaign
from space_env.industrial.campaign import AgentCampaignSession
from space_env.industrial.detour import detour_policy

case = detour_campaign({"horizon_sec": 240, "release_sec": 60})
session = AgentCampaignSession(case["configuration"])
session.step(
    detour_policy(session.observe(), case["public_contract"]),
    expected_revision=session.revision,
    idempotency_key="first",
)
```

## Постановки

- `forward_link_available=True`: доступен короткий r→s.
- Значение по умолчанию: короткое звено закрыто, работает r→t→s.
- `backup_link_available=False`: t→s тоже недоступен; пути нет.
- `forward_recovery_delay_sec=10`: исходно закрытый r→s открывается
  через 10 секунд после выпуска поздних заявок. Совместно с недоступным
  t→s проверяет обнаружение восстановления без отдельного task event.
- Унаследованные `fault_profile`, `bundle_ttl_sec`, `sink_memory_bits`,
  `ack_loss_probability` и `route_delay_sec` задают дополнительные ограничения.

Задержка восстановления допустима только при исходно закрытом звене.
Её значение — конфигурация среды/оценщика; агенту будущий момент открытия
не сообщается. Имя профиля, настройки и времена будущих событий не входят
в публичное наблюдение.

## Что публикуется

В `CampaignConfiguration` параметр `publish_detour_graph=True` требует
`publish_route_topology=True`. Фабрика включает оба. Наблюдение содержит
`detour_graph` с текущим временем измерения, состояниями объявленных
relay-звеньев и `custody_paths` — последовательностями подтверждённых
владельцев существующих продуктов. В граф попадают только команды
уже видимого каталога; будущие заявки отфильтрованы заранее.

Для каждого звена публикуются источник, получатель, продукт, действие,
текущий RF budget/rate и признак доступности с учётом текущего здоровья
радио/шины и safe mode. Признак не резервирует ресурсы и не гарантирует
свободную память, будущее окно или успех следующей команды.
Окончательный допуск и конкуренция за ресурсы остаются native.
RF-геометрия следует штатному `network_sample_sec`: время наблюдения графа
не означает непрерывного обновления геометрии между RF-сэмплами. Текущие
отказы и интервалы недоступности проверяются в текущем времени модели.
Текущий признак `receivers[actor].receiving` позволяет политике отложить
несовместимую наземную передачу или другую команду аппарата, который
прямо сейчас принимает ISL-фрагмент. Он соответствует штатной проверке
native admission и не является резервированием будущего приёмного окна.

Это **идеальная текущая централизованная информация**. Даже если отдельно
задержан `relay_routes`, этот граф, custody history, основной каталог,
маски и результаты команд остаются текущими. Режим не моделирует полную
информационную изоляцию бортовых агентов или задержки командного контура.
Чтение графа не меняет физическое состояние и не выполняет пробных передач.

## Политика обхода

`detour_policy` — отдельная детерминированная политика по публичным наблюдениям.
Для неё нужны `adaptive_routing=True` и `require_route_progress=False`:
ограничение статического расстояния из multihop не допускает длинный обход.

Для каждого допустимого первого перехода политика:

1. Проверяет текущую RF-доступность, native enabled mask и допустимый
   возраст маршрутного снимка.
2. Требует, чтобы текущий источник был последним подтверждённым владельцем,
   а получатель ещё не входил в историю custody этого продукта.
3. Исключает посещённые узлы из продолжения и ищет BFS-путь к объявленному
   ground sender по текущим доступным звеньям.
4. Среди допустимых первых переходов одного продукта оставляет варианты
   с наименьшим числом relay-шагов. Приоритеты заявок, обработка, съёмка
   и выбор между равными вариантами наследуются от `campaign_policy`.

Недостающий или не совпадающий с текущим временем граф не разрешает relay.
История предыдущих владельцев проверяется и при устаревшем маршрутном снимке.
При соблюдении native custody и этой политики каждый новый владелец уникален;
изменение доступности звеньев само по себе не создаёт цикл владения.
Произвольному агенту среда не запрещает плохие или обратные команды:
ограничение реализовано именно в базовой политике.

Пока остаются незавершённые request-bound relay-задачи, ожидание ограничено
одной секундой. Это позволяет обнаружить открытие радиолинии, даже если
оно не является task event и в момент ожидания нет активной передачи.
Политика не читает будущее время открытия. После выполнения заявок
этот опрос прекращается, чтобы не исчерпывать бюджет вызовов на горизонте.

Поиск текущего пути не является прогнозом будущего контакта и не гарантирует
глобального оптимума по времени, энергии или надёжности. Он может направить
данные в узел, чьё следующее звено откажет позже. После постоянной потери
радио владельца данные не создаются заново на другом аппарате.

## Проверка и генерация SFT/RL

```bash
python -m pytest -q tests/test_detour_campaign.py
python -m examples.modeling.detour_campaign_study --output artifacts/my-detour-study
python -m examples.modeling.detour_campaign_audit artifacts/my-detour-study
```

Исследование включает короткий путь, длинный обход, отсутствие пути,
восстановление связи/радио, короткий TTL, потерю владельца, задержанный
маршрутный канал и двухчасовую миссию. Сохраняются публичные tool-эпизоды,
конфигурации оценщика, native network reports и RL JSONL. Двухчасовая
успешная миссия экспортируется также как SFT.
Каждый экспорт повторно исполняет эпизод; отдельная проверка policy trace
пересчитывает действия именно через `detour_policy`.
Политика имеет происхождение `scripted_public`; обучения или инференса LLM
это исследование не подтверждает.
Профили — объявленные демонстрационные/регрессионные случаи, а не независимая
выборка для доказательства обобщения агента на неизвестные миссии.

Модель остаётся синтетической: конструктивная геометрия, J2, заданные
RF/RC/bus параметры, whole-product custody и идеальные внеполосные ACK.
Этот профиль не доказывает масштабируемость большой группировки или
независимо подтверждённую физическую точность.

## Зафиксированные результаты 16 ноября 2026

Квалифицированный набор: `artifacts/detour-qualified-20261116`.
Девять эпизодов экспортированы как RL; успешная двухчасовая миссия — также
как SFT. Каждый экспорт повторно исполнен. В `dataset-manifest.json`
перечислены только эти JSONL с контрольными суммами; все имеют split `train`.
Предварительный неполный `artifacts/detour-campaign-20261116` не входит в набор.

Шесть профилей завершились успешно, три дали ожидаемый неуспех:
нет пути, истёк TTL и потеряно радио текущего владельца.
Во всех квалифицированных эпизодах нет отклонённых командных решений;
неуспех миссии отражает ограничения исполнения, а не ошибку формата вызова.

В коротком обходном профиле 55 решений; последние поздние доставки
подтверждены через 21.08044 с после выпуска заявок. При восстановлении
звена — через 23.08054 с, радио — через 26.42846 с.
Двухчасовая миссия успешна за 78 решений: поздние заявки доставлены
через 21.08022 с после выпуска, результат сохранён до t=7200 с.

с общей наземной очередью; это не доказательство оптимальности политики.

Аудит проверил 557 публичных наблюдений, происхождение действий,
непрерывность и уникальность custody-путей, TTL и баланс битов/наземного зачёта.
Искажения TTL, delivered bits и истории с повторным владельцем отклонены
контролируемыми отрицательными проверками. Это аудит согласованности отчётов;
