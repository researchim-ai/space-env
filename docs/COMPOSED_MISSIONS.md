# Составные миссии в одном runtime

`CampaignSession` — отдельный центральный API последовательных фаз поверх
`TaskSession`. Аппараты, остаток топлива, продукты, выполняющиеся команды,
очереди измерений и фильтры навигации продолжают существовать при переходе.
Переход не создаёт новый симулятор и не выполняет опорные действия за агента.

## Контракт

- Один исходный scenario и один каталог действий TaskSpec без `goal`.
- От одной до 32 фаз с уникальными идентификаторами и обычными `MissionGoal`.
- Дедлайны абсолютные от начала сценария, строго возрастающие.
- Все фазы проходят предварительную проверку через штатный TaskSession:
  неизвестное оборудование, недоступный эталонный аппарат и запрещённые
  sensor-aware физические цели не обходятся через позднюю фазу.
- После каждого принятого шага оценивается только активная фаза. За шаг
  завершается максимум одна фаза; следующая проверяется на следующем шаге.
- Шаг ограничивается дедлайном и точной эпохой активной орбитальной цели.
- Провал фазы, конец native горизонта или исчерпание бюджета решений
  завершают всю миссию. Завершение всех фаз означает успех кампании.
- Ограничения энергии и топлива измеряются от общего начала сценария,
  не обновляются при смене фаз. Проверяются ограничения активной фазы.

Завершённая фаза — историческое достижение. Условия `maintain` не продолжают
автоматически проверяться после выхода из неё. Если состояние должно
сохраняться, повторите условие в последующей фазе. Проверки выполняются
на границах решений, а не непрерывно. Командное доказательство использует
`command_after_sec` из цели: при необходимости задайте его явно, чтобы
исключить команды предыдущих фаз.

## API

```python
from space_env.tasks import CampaignSession

session = CampaignSession(scenario, task_without_goal, {
    "id": "my-mission",
    "phases": [
        {"id": "first", "goal": first_goal},
        {"id": "second", "goal": second_goal},
    ],
})
result = session.step(
    {"a": ["burn"]}, expected_revision=0,
    idempotency_key="decision-0", advance_sec=1.0,
)
status = session.status()
restored = CampaignSession.from_checkpoint(session.checkpoint())
```

`observe(role)` возвращает исходную акторную проекцию, без физических
остатков целей и глобальных результатов кампании. `status()` и результат
`step()` предназначены центральному контроллеру/оценщику. Не передавайте
весь checkpoint агенту: он содержит сценарий и привилегированные данные.

`step()` возвращает исходный native transition отдельно от статуса кампании.
Native `terminated` относится к базовому эпизоду; финальный статус составной
миссии берите из `result["campaign"]["terminal"]`. Подсчёт завершённых фаз
монотонный; награда базового TaskSession сохраняет свою прежнюю семантику.
Новая схема reward shaping, Gym/PettingZoo и SFT/RL экспорт кампаний этим
API пока не заявляются. Существующий экспорт отдельных task-эпизодов остаётся
отдельным контрактом.

Checkpoint содержит исходный рецепт, журнал запросов и хешей ответов,
итоговый статус и native task checkpoint. Восстановление пересоздаёт миссию
и повторяет журнал, затем сравнивает всё состояние. Даже пересчитанный
внешний SHA не позволяет подменить статус успеха без соответствующего
исполнения. Идентичность исходников/зависимостей остаётся частью native replay.
Повтор запроса идемпотентен; изменение тела под прежним ключом отвергается.

## Локальная демонстрация

```bash
python examples/modeling/campaign.py --mission finite --output artifacts/my-campaign
python examples/modeling/campaign.py --mission eo --output artifacts/my-eo-campaign
python -m pytest -q tests/test_composed_missions.py
```

Пример использует короткий синтетический профиль с конечной тягой, непрерывным
питанием сенсора, оцениванием, native Ground-доставкой и отдельной фазой
подтверждения сохранённого результата. Запускает опорную политику и бездействие,
сохраняет checkpoints и проверяет холодное восстановление каждой попытки.
Второй профиль (`--mission eo`) выполняет съёмку, обработку и native доставку,
затем переориентацию того же аппарата. У команды slew задан допустимый
временной бюджет 20 секунд вместо исходного изолированного профиля 5 секунд:
после съёмки аппарат начинает манёвр из другой ориентации.

В локальном прогоне 10 ноября 2026 года получены четыре попытки: два успеха
опорной политики и два провала бездействия по дедлайну. Все четыре checkpoints
восстановлены холодным исполнением. Артефакты находятся в
`artifacts/composed-missions-20261110/`.
Это доказательство непрерывности исполнения, не квалификация реальной миссии.

## Следующие измеримые расширения

1. Полноценные фазовые наблюдения, разрешения действий и единый контракт
   Gym/LLM/SFT с раздельными public и trainer данными.
2. EO → обработка → ISL → Ground с динамическими заявками и отказами;
   опорные расписания должны быть перепланированы, а не просто сдвинуты.
3. Наблюдаемая относительная навигация и сближение с abort; независимая
   проверка динамики и непрерывная безопасность интервалов.
4. Длительные миссии с ресурсным износом и документированными областями
   применимости моделей.

Наличие контроллера фаз не делает эти новые физические режимы реализованными.
