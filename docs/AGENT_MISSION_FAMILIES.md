## Что запускается через общий интерфейс

- **`earth_observation`**: назначение доступных действий аппаратам, получение,
  обработка и доставка продуктов. Профили `nominal`, `new_demand`,
  `station_outage`. Основа — `OperationsSession` над native EO/CPU/ISL executor.
- **`communications`**: доставка прикладных потоков через межспутниковую связь и
  наземные каналы, custody, управление ограниченными ресурсами. Профили `nominal`,
  `outage`, `receiver_failure`, `cancel_inflight`, `pointing`, `low_memory`,
  `prefix`. Основа — `NativeServiceSession`; байты уже получены полезной нагрузкой,
  это не новый генератор изображений.
- **`proximity`**: оценка относительного состояния, импульсные манёвры,
  позиционная инспекция или отход. Профили `nominal`, `latency`, `blind`,
  `crossing`, `retreat`. Основа — `NativeProximitySession`: две нелинейные
  центрально-гравитационные орбиты и синтетические Cartesian-position EKF.
- **`fault_management`**: диагностика, ограниченные попытки восстановления,
  изоляция и продолжение полезной работы. Профили `resettable`, `permanent`,
  `external_repair`. Основа — `OperationsSession` с идеализированным ground BIT/reset.

Итого **4 семейства, 18 профилей, 3 типа executor**. Семейства EO и восстановления
используют один executor с разными постановками. Это не 18 независимых физических
моделей и не измерение разнообразия промышленного рынка.

Расход энергии, тепло, память, топливо и время — сквозные ограничения там, где
их действительно учитывает выбранный executor. Новый каталог не обещает все
ресурсы в каждом профиле. Полная распределённая автономия, контактная стыковка,
манипуляции и перекачка топлива через этот API отсутствуют. Орбитальные постановки
и развёртывание группировки остаются доступны через отдельный native task API
`space_env.tasks.catalog`; их адаптация к industrial-интерфейсу отмечена как roadmap.

## Python: выбрать постановку и подключить LLM

```python
from space_env.industrial.missions import mission_families, make_episode
from space_env.simulation.snapshot import canonical_json

catalog = mission_families()  # JSON metadata, без создания runtime
mission = make_episode(
    "earth_observation/new_demand",
    split="train",
    policy_origin="external_llm",
    max_calls=128,
)

# Передайте модели mission.record()["messages"] и mission.tool_schema().
# Возвращённые JSON arguments применяются обычным контрактом:
# response = mission.call(call_id, arguments_json)
# Повторяйте, пока не mission.done.
```

`policy_origin` — декларация происхождения действий, не доказательство inference.
Источник и сведения об окружении сохраняются в privileged record для replay.
Собственную реальную модель этот интерфейс не загружает и не обучает.

`make_session(id)` возвращает существующую decision session без LLM-обёртки.
`mission_recipe(id)` возвращает **privileged** конфигурацию для экспериментатора.
Она содержит будущие события и иногда checkpoint физического префикса: её нельзя
передавать агенту. Неизвестные ID и направления roadmap отклоняются, без fallback.

## Общая постановка для агента

`make_episode` добавляет в первое user message поле `task_text`: цель, fidelity,
ограничения и правило пользоваться текущими наблюдениями. Текст общий для всего
семейства: он не содержит ID профиля, времени будущего отказа, списка скрытых
заявок, recipe digest или готового плана. Конкретные опубликованные цели и
ограничения агент получает из текущего observation.

Одинаковый текст семейства не делает наблюдения разных профилей одинаковыми:
например, уже известные ресурсы и параметры сенсоров могут различаться. Это
не доказательство полной неразличимости сценариев или отсутствия всех side channels.

`IndustrialEpisode(..., task_text="...")` также принимает собственный **публичный**
бриф до 8192 UTF-8 байт. Caller отвечает за отсутствие секретов в таком тексте.
Текст хранится в record и повторно проверяется при replay. В старых вызовах без
`task_text` структура записи и сообщений сохранена; исторические source-bound
записи всё равно проверяются только с их исходной версией кода и окружения.

```python
from space_env.industrial.agent import verify_episode, export_training

# record = mission.record()  # после взаимодействия
# verify_episode(record)
# export_training(record, "new-output.rl.jsonl", format="rl")
# export_training(record, "new-output.sft.jsonl", format="sft")
```

Экспорт разрешён для `train` split с явным происхождением политики. SFT требует
успешного эпизода без ошибок; RL может содержать неуспех и исчерпание бюджета.
Проверка replay обязательна. Обучающий JSONL получает causal messages/rewards,
а не hidden checkpoint/configuration. Собственный `task_text` тоже попадёт в
обучающие сообщения, поэтому его нужно считать агентским входом.

## Gym

```python
import json
from space_env.industrial.missions import make_env

env = make_env("communications/nominal", max_calls=128)
observation_text, info = env.reset(seed=7)
observation = json.loads(observation_text)
assert "task_text" in observation
# env.step(arguments_json) — полный envelope с action, expected_revision,
# idempotency_key; JSON action, а не индекс дискретного действия.
env.close()
```

Цель доступна в observation после reset и каждого шага. Trainer metrics остаются
в `info["trainer_only"]`, их нельзя подавать policy как observation.
Seed меняет только сенсорные реализации в поддерживающих это профилях;
это не генератор новых группировок, орбит, заявок и отказов.

## Локальный запуск

```bash
python -m space_env.industrial.missions --output artifacts/my-catalog.json
python -m space_env.industrial.missions \
  --mission earth_observation/new_demand --policy public \
  --output artifacts/my-eo-episode.json
python -m space_env.industrial.missions \
  --mission proximity/latency --policy wait --max-calls 2 \
  --output artifacts/my-relative-smoke.json
```

CLI проверяет replay перед записью эпизода. Существующий output отклоняется.
`public` — scripted policy по текущему observation; `wait` — бездействие. Это
не запуски LLM и не оптимальные решения. Двухшаговый smoke обычно заканчивается
по call budget и не свидетельствует о выполнении миссии.

## Следующие большие блоки

1. **Орбиты и развёртывание.** Адаптер существующего native TaskSession с тем же
   качеством публичной цели, инструментов, termination/reward и cold replay.
   Сначала сохранить смысл существующих задач, затем расширять генерацию.
2. **Настоящая генерация постановок.** Версионированные распределения группировок,
   заявок, ресурсов и отказов; раздельные train/development/test progenitors.
   Счётчик профилей не заменяет проверку разнообразия и сложности.
3. **Связанные большие миссии.** Одна native timeline, сохранение продуктов и
   ресурсов между этапами, динамическая цель, отсутствие двойного учёта топлива,
   энергии и данных. Сейчас семейства не сшиваются произвольно.
4. **Распределённые агенты.** Отдельные информационные границы, задержки сообщений,
   конкуренция за ресурсы и согласование. Центральный union observations этим
   свойством не обладает.
5. **Измеренное обучение.** SFT и RL на обособленной генерации, фиксированные
   бюджеты, сравнение с эвристиками и оптимизационными методами, удержанные
   комбинации сбоев и реальные запуски моделей с provenance.
6. **Достоверность.** Независимые сравнения физических профилей в заявленных
   областях применимости. Нужны отдельные доказательства для sensor/bus/RF,
   нецентральных сближений, долгих миссий и масштабирования.

[Предыдущий физически связанный блок и его измерения](NATIVE_COUPLED_MISSIONS.md)
остаются историческими: обновление исходников не перепривязывает старые receipts.

## Проверки этого обновления

Локальный targeted regression: **65 тестов прошли**. Проверены существующие
industrial tool/export/replay контракты, native service/proximity и новый слой
семейств: отсутствие построения runtime при discovery, явное отклонение
неподдержанных направлений, одинаковый публичный бриф при разных будущих событиях,
доступность цели в Gym, ограничение call budget, успешная нелинейная инспекция,
SFT/replay с брифом и отклонение изменённых сообщений.

Собран wheel версии 0.134.0: побайтно сверены **367 Python/JSON файлов**.
Из отдельного cwd выполнены discovery всех 18 профилей и двухшаговый native
proximity эпизод с replay. Smoke использует уже установленные зависимости,
не доказывает чистую установку или полную квалификацию wheel.

Полные локальные записи и короткие проверки находятся в игнорируемой Git
директории `artifacts/agent-mission-families-20261113/`. Источники текущего
прогона связываются отдельно от результатов предыдущего обновления.

Матрица этого обновления включает **36 двухшаговых smoke** (18 профилей × `wait`
и `public`) и **4 полных scripted-public миссии**, по одной на семейство. Все
эпизоды проверены replay. Полные запуски завершились успешно:

- EO с новой заявкой: 4/4 запросов, 29 решений, без environment rejections.
- Native communication nominal: оба потока, 700 000 бит к срокам.
- Native proximity latency: выполнена позиционная инспекция по оценке состояния.
- FDIR external repair: 4/4 запросов, 7 maintenance attempts; часть попыток
  восстановления неэффективна. Это не семь успешных ремонтов.

Получены **3 SFT и 4 RL строки-демонстрации**. SFT для FDIR закономерно отклонён:
успешная миссия содержала отрицательную обратную связь по recovery actions.
Исходный `report.json` сохраняет это исключение; `qualification.json` явно
классифицирует его как ожидаемый запрет SFT и сохраняет проверенный эпизод.
Неуспешный экспорт не скрыт и не превращён в успешную SFT-демонстрацию.

Это тот же публичный synthetic recipe lineage для разработки и оценки, а не
независимые holdouts, результаты обучения LLM или доказательство превосходства.
