# Выбор эпохи манёвра и общие слоты диспетчеризации

Продолжение этого этапа: [причинные изменения dispatch во время миссии](DYNAMIC_ORBIT_REPLANNING.md).
Ниже описаны статические окна и их исторические измерения; новый блок проверяет
восстановимые и критические изменения отдельно.

Обновление 15 ноября 2026 года расширяет орбитальное семейство окнами запуска.
В общем API **5 семейств и 27 стартовых профилей**. Новые ID:
`orbit_and_deployment/windowed_train`, `windowed_development`, `windowed_test`.

## Чему учится агент

Выбрать направление и время конечной тяги, дождаться подходящего окна и
распределить общий ресурс отправки команд между аппаратами. Запускать все
двигатели немедленно недостаточно: опубликованные цели соответствуют
разным ненулевым эпохам манёвров.

Поддерживаются **2–4 аппарата**, горизонт 40–90 s. Для каждого даны два
противоположных burn templates и три заранее опубликованных полуоткрытых
окна запуска. Они выбраны на сетке 0/5/10/15/20 s с шириной 5 s; между окнами
могут быть промежутки недоступности. Первый вариант эпохи t=0 — допустимый
отвлекающий выбор, а не подсказка правильного запуска.

Одновременно доступен **один слот отправки команды запуска за decision step**;
во всей задаче допускается один burn на аппарат. Двигатели разных аппаратов
могут затем работать одновременно. Этот ресурс — synthetic dispatch admission
в `OrbitSession`, **не RF uplink, не общая мощность двигателей и не модель
вычислительного процессора**. Native TaskSession сохраняет прежние per-role
и физические ограничения; адаптер добавляет явно объявленные ограничения
диспетчеризации.

## Постановка и физика

Генератор сначала задаёт физические параметры прежнего phasing family, затем
выбирает разные эталонные эпохи среди 5/10/15/20 s. Разные аппараты получают
разные эпохи, поэтому конструктивное управление удовлетворяет общему слоту.
Цели рассчитываются как coast до запуска и finite thrust с последующим coast:

\[
\mathbf x(t_g)=\Phi_0(t_g,t_s+\tau)
 \circ\Phi_F(t_s+\tau,t_s)
 \circ\Phi_0(t_s,0)\,\mathbf x_0.
\]

Здесь \(\Phi\) обозначает нелинейное численное распространение состояния,
а не матрицу линейного перехода. Используется отдельный RK4 с шагом 0.005 s,
центральная гравитация и аналитическая убыль массы. Общие константы и исходные
условия совпадают с native моделью; аппаратной калибровкой это не является.

Физика исполнения остаётся у native TaskSession: орбита, конечная тяга, масса,
ресурсный surrogate, goal, reward и временная ось. Адаптер не списывает топливо
или энергию повторно.

## Контракт инструментов

`OrbitAction` остаётся `{"action_ids": [...]}`. Observation дополнен:

- `launch_windows`: опубликованные окна для каждого действия;
- `dispatch_capacity`: число стартов за шаг;
- `launched_actors`: история принятых запусков;
- `one_burn_per_actor`: правило однократного запуска.

Action mask учитывает текущее окно и уже выполненные запуски. Native причины
недоступности не подменяются; дополнительная причина хранится в `window_reason`.
Окна — известные ограничения планирования. `private_timing` и reference schedule
не публикуются в observation или сообщениях агента.

Неизвестное имя действия отклоняется до исполнения, как прежде. Известная
команда вне окна, повторный запуск и превышение capacity дают отрицательную
feedback, штраф 0.1 и **native coast на один шаг**. Двигатель не запускается,
но время проходит. Отклонённый весь batch не частично исполняется.

- `dispatch_rejections` — отказы дополнительного admission-слоя;
- `native_rejections` — отказы TaskSession.

Эти счётчики различаются. Idempotency retry не повторяет coast или штраф.
State witness и replay включают логическое состояние запусков.

## Базовая политика

Public policy заново прогнозирует результат для доступных вариантов направления
и будущих опубликованных эпох из текущего состояния. Использует собственный
RK4 h≤0.25 s и открытые параметры двигателей; native forecast API и закрытое
расписание не вызываются.

Она выбирает минимальную конечную ошибку для каждого ещё не запущенного
аппарата и отправляет готовые сейчас команды в рамках общего слота. Это
простая рекурсивная эвристика по small discrete catalogue. Она **не является
общим оптимальным совместным планировщиком**: конструктивные эталонные эпохи
различны, а более общие конфликты приоритетов/сроков ещё не моделируются.

## Использование

```python
from space_env.industrial.orbits import OrbitSession
from space_env.industrial.missions import make_episode

session = OrbitSession({
    "actors": 4,
    "generation": {"split": "train", "seed": 17, "windows": True},
})
episode = make_episode("orbit_and_deployment/windowed_test")
# episode.split == "test"; перемаркировать в train нельзя.
```

```bash
python -m space_env.industrial.phasing_corpus --windows \
  --samples-per-split 2 --actors 2 \
  --output artifacts/new-windowed-corpus

python examples/modeling/export_phasing.py \
  --corpus artifacts/new-windowed-corpus \
  --output artifacts/new-windowed-training
```

Сохраняются непересекающиеся диапазоны горизонта/тяги train/development/test,
строгий split provenance и train-only export. Physical identity включает цель,
опубликованные окна по аппаратам и dispatch/one-burn ограничения; command IDs
не используются как доказательство физического разнообразия.

## Что ещё не реализовано

Нет перебоев связи, внезапного закрытия окон, манёвров после отказа двигателя,
неполной наблюдаемости, многодневного развёртывания, body-frame actuation,
J2/drag/SRP или непрерывной collision guarantee. Дополнительные эффекты не
подразумеваются словом «окно». Семейство immediate phasing остаётся доступно
с `windows=False` (default) и поддерживает прежние 2–8 аппаратов.

Следующие блоки: конкурирующие задачи и сроки с проверяемой недостижимостью,
динамические изменения во время исполнения, более общие совместные планировщики
и измеренное обучение агентов на удержанных сочетаниях условий.

## Локальные результаты

Проверены шесть windowed случаев с двумя аппаратами: по два случая из каждого
split, политики `wait` и `public` — **12 полных эпизодов с replay**.
Дополнительно исполнен test-случай с четырьмя аппаратами с теми же двумя
политиками — ещё **2 эпизода с replay**. Public выполнил все 7 случаев,
wait не выполнил ни одного; dispatch/native rejections у public равны нулю.
Эти небольшие локальные измерения не дают статистической оценки надёжности,
не измеряют обученную модель и не сравнивают систему с внешними симуляторами.

Негативные тесты отдельно проверяют преждевременные старты, две команды для
**разных** аппаратов при одном слоте, закрытые полуоткрытые окна и второй
запуск того же аппарата. Отклонённые команды не расходуют топливо, но сохраняют
native ход времени. Приватное расписание не попадает в transcript.

Данные хранятся в игнорируемой Git директории
`artifacts/phasing-windows-20261115/`. Исторические receipts предыдущих блоков
не перепривязывались к текущим исходникам.

Итоговый targeted regression: **71 тест прошёл**. Получены **2 SFT и 4 RL строки**
только из train; development/test сообщения в обучающие JSONL не экспортированы.
Обучение модели не выполнялось.
