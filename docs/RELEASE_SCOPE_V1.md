# Выпускаемая область Space Env v1

Машиночитаемый scope находится в `src/space_env/configs/release_scope_v1.json` и
включается в wheel. Это локальная Python-библиотека для моделирования и обучения,
с native runtime, ролями, Gym/MARL, операторским интерфейсом, replay и RL/SFT.
Единицы и системы координат явные: GCRS, геодезические координаты наземных точек,
секунды, метры, м/с, Wh и биты. Каждый физический режим имеет собственный контракт;
успех одной цепочки нельзя переносить на все модели библиотеки.

## Поддерживаемые контракты

- [Матрица физической квалификации](validation/PHYSICS_QUALIFICATION_MATRIX.md):
  область применимости, эталоны и открытые проверки по физическим профилям.
- [Полные орбитальные циклы](validation/FULL_ORBIT_MISSIONS_V1.md) и
  [rigid missions](validation/RIGID_MISSION_CONTRACT.md): отдельные режимы.
- [Связанные приводы](validation/FIXED_CLOCK_ACTUATORS_V1.md): fixed clock,
  колёса/RCS, вращающаяся тяга и ресурсный учёт.
- [Планирование цепочек](validation/FORECAST_CHAINS_V1.md): ограниченный kinematic
  planner, до4 actors/16 stations/64 requests; ideal geometric radio и metadata.
- [Аварии](validation/INCIDENT_RECOVERY_V1.md),
  [живые агенты](validation/ACTOR_POLICY_JOURNAL_V1.md) и
  [новые заявки](validation/VERSIONED_DEMAND_V1.md): явные epoch, authority,
  immutable prefix, versioned catalogue и native replay.
- [B12 benchmark](validation/RELEASE_BENCHMARK_V1.md): общий forecast, ограниченный
  поиск, фиксированные geometry groups, неизменный знаменатель и отказные строки.

## Что означает приёмка B12

Проверка установки подтверждает один конкретный wheel и полный выбранный dependency
closure в чистом venv Python3.12. Профили reference/fast отдельно проверяют код;
их счётчики пересекаются. Текущий порядок работы: локальные тесты и ручной запуск
примеров, без CI и обязательных удалённых проверок. Python3.10 имеет отдельный fast-профиль;
зафиксированный расширенный scientific lock предназначен для3.11/3.12.

32-case suite содержит train/development/test geometry groups. Это физически
различные входы и фиксированный benchmark, а не подтверждённая случайная выборка
реальных миссий. Три алгоритма пользуются общей forecast-информацией. При одинаковых
приоритетах и дедлайнах rule-based и priority baselines могут совпадать; это не
доказательство превосходства более сложного поиска. Нужны разнообразные бизнесовые
распределения и более широкие независимые данные для следующей версии benchmark.

Профиль1GiB проверяет отказ при недостаточном хранении полного набора evidence.
Профиль4GiB повторяет те же физические миссии с другой ёмкостью хранения; такие
повторы не добавляют независимых test cases. Оба результата сохраняются.
Измерения параллельных групп относятся к общему host, не к изолированному SLA.
Peak RSS является измеренным gate, не OS isolation. Artifact accounting не
является гарантией защищённого multi-tenant хранения.

## Что не заявляется

Flight qualification, цифровой двойник конкретного спутника, точность научной
обработки изображений, measured sensor calibration и универсальность всех миссий
не следуют из этих проверок. Scientific image products здесь не создаются;
metadata/resource surrogate помечен явно. SFT-кандидат с выполненной целью не
равен экспертной демонстрации; suite-level teacher gate независим.

Лицензия проекта указана как Apache-2.0 и включена в wheel. Инвентарь сторонних
лицензий — исходные метаданные, не завершённая юридическая проверка. Advisory audit
имеет дату и сохраняемый ответ; отсутствие известных записей не доказывает
отсутствие неизвестных дефектов. Первичные findings и обновления не удаляются.

## Критерий выпуска

[Актуальный план](RELEASE_FINISH_PLAN.md) задаёт порядок разработки: локальные
тесты и ручной запуск, без CI и обязательных приёмочных кампаний.
Для выпуска нужны рабочая установка, локальные тесты, понятные примеры и
описание известных ограничений. Пользователь самостоятельно запускает Studio. Экспертная
квалификация teacher, реальные измерения C2 и hosted Q7 имеют самостоятельные
критерии. Коммит, push, tag и публикация выполняются пользователем.

## Данные для обучения

Для B12 следует применять [explicit split exporter](validation/RELEASE_DATA_SPLITS_V1.md),
а не legacy-метки native bundles. Созданы14400 RL rows:3600 train,3600 development,
7200 test; SFT остаётся закрытым из-за непройденных teacher-gates. Source bundles
сохраняются без изменения как replay/evaluation evidence. Большие generated
архивы находятся локально и исключены из обычного git add; маленькие receipts,
входы и recipes предназначены для review. Дополнительные эксперименты пользователь запускает вручную по желанию.
