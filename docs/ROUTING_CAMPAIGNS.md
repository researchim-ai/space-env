# Переключение маршрутов при отказах ретрансляторов

`space_env.tasks.routing_campaign.routing_campaign` расширяет непрерывную
четырёхаппаратную EO → обработка → ISL custody → наземная доставка миссию.
Обе камеры могут передавать свой продукт любому из двух ретрансляторов.
Для каждой пары продукт/ретранслятор есть отдельная команда наземной доставки.
Исполнение использует существующие физические, ресурсные и DTN механизмы;
перепланирование не создаёт копий продуктов и не сбрасывает энергетику.

```python
from space_env.tasks.routing_campaign import routing_campaign
from space_env.industrial.campaign import AgentCampaignSession
from space_env.industrial.campaign_policy import campaign_policy

case = routing_campaign({
    "horizon_sec": 240,
    "release_sec": 60,
    "fault_profile": "mid_transfer",
})
session = AgentCampaignSession(case["configuration"])
action = campaign_policy(session.observe(), case["public_contract"])
session.step(action, expected_revision=session.revision, idempotency_key="first")
```

## Что видит агент

Наблюдение кампании с DTN содержит `relay_routes`: текущую доступность,
причину недоступности, скорость/дальность радиолинии, свободную память
приёмника и время измерения/сэмпла радиолинии. Учитываются текущие отказы
радио/шины, safe mode, SOC, занятость и резервирование памяти под передачи
и задания обработки. Окончательный допуск команды остаётся за исполнителем.
Снимок не гарантирует доступность линии на всю длительность команды.

Варианты для ещё не объявленных заявок скрыты вместе с каталогом команд.
Будущие времена отказов и восстановления не передаются политике.
Это идеальная централизованная телеметрия, а не модель распределённого
знания, задержек команд или бортового сетевого протокола.

`adaptive_routing=True` включает выбор только доступных relay-команд.
При равном приоритете заявки и сроке политика предпочитает большую
текущую скорость, затем свободную память и стабильный идентификатор.
Если сведений о маршруте нет, такой маршрут не выбирается.
По умолчанию режим выключен; прежняя политика сохраняет порядок выбора.
Это реактивная эвристика без прогноза или гарантии оптимальности.

## Отказы и сохранность данных

- `none`: исходные маршруты a→r и b→s.
- `before_transfer`: отказ радио r до начала передачи; камера a выбирает s.
- `mid_transfer`: отказ r во время сериализации; после завершения отменяемой
  попытки камера a передаёт целый исходный продукт через s.
- `after_custody_recover`: r уже принял продукт; доставка ждёт восстановления r.
- `after_custody_permanent`: r принял продукт и навсегда потерял радио;
  миссия не выполняет обязательство доставки этого продукта.
- `all_relays_down`: оба приёмника недоступны до передачи; миссия неуспешна.

До подтверждения custody исходная копия сохраняется. Частичная сериализация
прерванной попытки учитывается как затраченные биты; фрагменты не переносятся
между приёмниками. При новой попытке срок жизни исходного bundle не продлевается.
После подтверждения custody политика не может вернуть продукт на камеру
или создать его на другом спутнике. Постоянный отказ владельца здесь
невосстановим: каталога передачи между ретрансляторами нет.

В этой постановке ограничения явно допускают историю отказов ретрансляторов,
сохраняя требования здоровья камер, энергетические лимиты, сроки доставки
и единый горизонт. Критерий успеха исходной `relay_campaign` не изменён.

## Локальное воспроизведение

```bash
python -m pytest -q tests/test_routing_campaign.py
python -m examples.modeling.routing_campaign_study --output artifacts/my-routing-study
```

Исследование сохраняет конфигурации оценщика, публичные tool-эпизоды,
нативный сетевой отчёт и RL JSONL для всех шести случаев. Для успешного
переключения во время передачи сохраняется также SFT JSONL.
Экспорт заново исполняет эпизод; проверка policy trace пересчитывает действия
из публичных наблюдений. Политика обозначена `scripted_public`:
этот набор демонстрирует генерацию данных, а не обучение или оценку LLM.

Область применимости: конструктивная синтетическая геометрия, J2, заданные
RF/аккумуляторные/тепловые параметры, whole-product custody и идеальные
внеполосные ACK. Прогоны подтверждают программные свойства этой постановки,
не являются независимой физической калибровкой или полётной сертификацией.
Задержанный маршрутный канал реализован отдельно (ссылка ниже).
Следующие расширения: согласованная задержка остальных каналов, прогнозируемые окна,
межретрансляторная маршрутизация и масштабные разнообразные группировки.
